# ADR-075: 릴리스와 조회 옵션에 종속된 제한 용량 메모리 결과 캐시

- 상태: accepted
- 날짜: 2026-11-07
- 결정자: 사용자(현재 장비 내 세 차례 성능 개선), Codex

## 컨텍스트

영속 결과 캐시는 적중 때마다 `geo_cache`를 UPDATE한다. 같은 키에 동시 요청이 들어오면
행 잠금과 DB 왕복이 반복된다. v2 변환·검색·선택적 geometry 경로는 영속 캐시 적중 뒤에도
실행될 수 있다. 현재 API 메모리 한도는 1.5GiB, 공용 PostgreSQL 한도는 3GiB다.

## 결정

- `AsyncAddressClient`별 메모리 결과 캐시를 둔다. 기본 보관 예산은 64MiB이며
  `KTG_CACHE_MEMORY_MAX_BYTES=0`으로 끈다. `KTG_CACHE_ENABLED=false`는 두 결과 캐시를 끈다.
  TTL은 300초다. 예산은 직렬화한 응답·키·보수적 항목 오버헤드의 합이며 프로세스 RSS 한도가 아니다.
- LRU로 축출하고 예산보다 큰 응답은 보관하지 않는다. v1 중간 결과와 v2 최종 결과가 같은 예산을 쓴다.
  주소·좌표를 반올림하거나 정확한 `total`을 생략하지 않는다.
- 활성 릴리스 지문과 전체 조회 옵션으로 키를 구분한다. 기존 데이터셋 지문 캐시의 10초 TTL은 유지한다.
  지문이 없거나 외부 fallback을 요청하면 결과 메모리 캐시를 우회한다.
- 성공한 결과만 보관한다. `NOT_FOUND`·오류·`geometry_error`가 있는 응답은 보관하지 않는다.
  ADR-071의 요청 간 geometry 캐시 금지는 **정상 결과의 제한 용량 캐시**에 한해 이 결정으로 수정한다.
  보조 geometry 실패는 다음 요청에서 다시 시도한다.
- 같은 키의 진행 중 요청은 공유한다. 공유 작업은 최대 128개이며 초과 키는 기존 조회를 실행한다.
  한 요청의 취소가 다른 대기자를 취소하지 않고, 마지막 대기자가 취소하면 DB 작업도 취소한다.
- 응답은 호출마다 따로 역직렬화하고 v2 `query_id`도 새로 발급한다. 가변 GeoJSON·metadata를
  호출자 간에 공유하지 않는다. 캐시 종료·초기화 중인 이전 작업은 새 캐시를 채우지 않는다.
- 기존 SDK 입력 모델이 허용하는 비유한 bbox는 JSON 변환에서 null로 바뀌므로 v2 최종 응답
  메모리 캐시를 우회한다. 입력 검증·기존 응답은 바꾸지 않으며 유한 bbox와 하위 v1 캐시는 유지한다.
- 공개 API의 인증은 캐시 조회 전에 기존 절차대로 실행한다. 권한·외부 키·사용자 정보를 캐시하지 않는다.

## 근거와 결과

반복 조회의 DB 왕복·쓰기와 선택적 geometry 재조회를 줄이면서 현재 메모리 예산에 보관량을
제한한다. 별도 캐시 서버와 의존성을 추가하지 않는다. 영속 캐시는 프로세스 간 공유와 첫 조회에
계속 사용되며, 메모리 미적중 경로의 기존 UPDATE 비용은 남는다.

`ktg_memory_result_cache_lookups_total{service,outcome}`으로 유한 종류의 hit·miss·coalesced·bypass를
관측한다. 기존 DB 캐시 hit 통계는 DB 경로의 값이며 메모리 적중을 포함하지 않는다. 주소·키를
메트릭 label에 넣지 않는다. 고유 조회와 프로세스 재시작 후 첫 조회는 메모리 적중 효과를 받지 못한다.
