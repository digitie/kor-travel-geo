# ADR-073 — 원천 좌표를 보존하고 검증된 좌표만 서빙한다

- 상태: 수락 — 2026-10-31 사용자 선택 1번에 따른 구현. 운영 반영·전체 재검증은 별도 완료 확인이 필요하다.
- 관련: ADR-012, ADR-017, ADR-069, ADR-072

## 배경

202610 폴더의 전국 전체분 적재는 원천 7개 완료 뒤 정합성 ERROR로 중단됐다. 위치정보요약 원본과 DB를 대조한 표본에서 약 179~181km의 좌표 오류가 원본에도 있음을 확인했다. 주소 연결 순서·읍면동 코드·도로 관할 코드 문제는 별도로 수정했으나 원본 자체의 좌표 오류를 해결하지는 않는다.

사용자는 공식 정정 원천을 기다리거나 오류를 허용해 강제 승격하는 대신, 불량 좌표의 서빙 격리와 검증된 대체 좌표 적용 후 정상 승격을 선택했다.

## 결정

1. 원본 ZIP과 원천 테이블의 좌표·식별자·건수는 보존한다. 격리로 원본을 삭제하거나 임의 좌표로 덮어쓰지 않는다.
2. 기존 원천 우선순위로 선택될 좌표를 검사한다. 출입구는 대응 건물 도형에서 500m를 초과하면 격리한다. NAVI 중심점은 대응 건물 도형 안에 있어야 한다. 빈 좌표, 기준월 불일치·누락, 검증에 필요한 건물·우편번호·읍면동 도형 누락, 해당 우편번호·읍면동 경계 밖 좌표도 격리한다. 거리 단위는 EPSG:5179의 m이고 경계 포함은 `ST_Covers`를 사용한다.
3. 격리한 주소의 대체 좌표는 같은 도로·건물구분·본번/부번·읍면동·기준월의 NAVI 중심점에서 찾는다. NAVI의 실제 건물관리번호로 연결한 건물 도형이 정본 주소의 법정동 10자리와 주소키에도 일치해야 한다. 그 건물·우편번호 구역·읍면동 모두 안에 있는 후보만 채택한다. 동률은 원본 건물관리번호 순으로 정한다.
4. 검증된 대체 후보가 없으면 그 주소의 서빙 좌표를 NULL로 둔다. 원본 또는 미검증 NAVI 좌표로 다시 fallback하지 않는다. 주소 행 자체는 MV에 남으며, 좌표 미제공 건수는 C3과 격리 지표에 기록한다.
5. 정본 주소와 연결되지 않는 SHP 도형은 원천에 보존하고 격리 이력으로 기록한다. 일반 건물 도형 조회는 실제 서빙 MV의 주소키에 연결되는 도형만 반환한다. C2는 원본 위반 수를 그대로 보고하며 미격리 위반이 하나라도 있으면 ERROR다. 서빙 제외가 확인된 격리 위반은 WARN으로 남긴다.
6. C4·C6·C7은 MV와 같은 격리·대체 좌표를 검사한다. 실제 서빙 좌표의 거리·경계 위반은 기존 기준으로 ERROR다. 격리한 원천 위반은 삭제하지 않고 WARN과 `quarantined_count`, `replaced_count`, `without_coordinate_count`, 원본 표본으로 구분한다. 50m/500m 거리 임계값과 경계 포함 기준은 완화하지 않는다.
7. `forced_promotion`을 사용하지 않는다. 파일 무결성·적재·미격리 정합성 오류의 차단은 유지한다.

## 저장과 실행

manifest 원문도 판정 이력에 함께 보존한다. 시간대가 다른 연결에서도 같은 판정을 찾도록 manifest 시각은 epoch로 정규화한다. 검사 완료·MV 생성·게시 시 입력에 대응하는 완료 판정을 확인하며, 입력이 바뀌면 이전 판정으로 게시하지 않는다.

`serving_quality_runs`는 정책 버전과 적재 manifest 지문에 대응하는 판정을 기록한다. `serving_coordinate_quarantine`는 판정별 원본 좌표·원천 식별자·파일·기준월·사유·주소 속성과 선택한 대체 좌표의 출처를 보존한다. 이전 판정 이력을 지우지 않는다. Alembic 0031과 신규 DB의 `SCHEMA_SQL`에 동일하게 정의한다.

판정은 하나의 트랜잭션에서 계산하고 완료 시각을 기록한 뒤 사용한다. 입력 manifest가 바뀌면 이전 판정을 재사용하지 않는다. 유지보수의 링크 해소 뒤 정합성 검사와 공식 MV 갱신 경로에서 판정을 준비한다. 독립 검사·독립 MV 갱신은 항상 새로 판정한다. 전체 배치는 검사 보고서의 판정 ID를 MV 자식에게 전달해 같은 판정을 사용하며, 입력 또는 판정 ID가 맞지 않으면 게시를 차단한다. 정책이나 선택 규칙을 바꾸면 정책 버전도 바꿔야 한다.

두 테이블은 적재·검증용이며 공개 조회는 결과가 반영된 `mv_geocode_target`을 읽는다. 판정 UUID만 바뀌어도 서빙 데이터 지문이 달라지는 일이 없도록 ADR-069의 서빙 내용 지문에는 판정 메타데이터를 추가하지 않는다. 실제 좌표·좌표 출처 변경은 기존 MV 지문으로 검출한다. 백업은 판정 테이블과 원천을 함께 보존한다.

품질 CSV에 `serving_coordinate_quarantine.csv`를 추가해 원본과 대체 좌표·출처·사유를 확인한다. CSV의 `limit`과 관계없이 DB에는 전체 격리 이력을 남긴다. 최종 운영 매뉴얼에는 실측 격리·대체·좌표 미제공 수와 원본 성공 화면을 기록한다.

## 검증과 한계

실제 PostgreSQL/PostGIS 회귀에서 수정 전 먼 좌표 선택을 재현하고, 검증된 대체·대체 부재·다른 기준월·다른 주소·다른 법정동·건물 밖·우편번호 밖·읍면동 밖·경계 포함을 확인한다. 원천 좌표 보존, 입력 변경 시 재판정과 이전 이력 보존, 미격리 C2 오류 차단도 확인한다.

격리는 원천 제공자의 정정이 아니다. 좌표를 제공하지 못하는 주소가 생길 수 있고, 동일 주소의 NAVI 대체가 실제 출입구 위치를 뜻하지는 않는다. 대체한 좌표의 `pt_source`는 `centroid`를 유지한다. 신규 정상 릴리스는 전체 정합성·MV·실제 UI 검증 뒤에만 완료로 기록한다.
