# ADR-074: 완료 원천을 검증하고 정합성 단계부터 새 배치로 재개한다

- 상태: 승인
- 날짜: 2026-10-31
- 결정자: 사용자 요청에 따른 Codex

## 배경

전체분은 원천 적재가 끝난 뒤 정합성 오류로 실패할 수 있다. 기존 실행은 원천→정합성→MV를 한 Dagster 작업 본문에서 처리하고 완료 자식의 재인수를 금지하므로, 같은 단계를 재실행해도 정합성부터 이어갈 수 없다. 실제 전국 원천 적재에는 약 20시간이 걸렸다.

## 결정

기존 재구축 요청에 선택 필드 `resume_from_batch_id`를 추가한다. 완료 원천을 재사용하고 새 전체 배치에서 정합성→ERROR 게이트→MV→서빙 릴리스를 실행한다. 이전 실패 배치와 완료 자식은 수정하거나 새 성공 작업으로 복제하지 않는다.

- 같은 매칭 세트·원천 그룹·파일 식별자·기준월·SHA256이며 모든 원천 자식이 완료된 실패·취소 배치만 허용한다.
- 원천 manifest의 기준월·건수·갱신 시각이 완료 작업과 일치해야 한다. 이후 다른 원천 쓰기가 시작됐거나 실행·대기 중인 적재가 있으면 거부한다. 재구축 도중 비운 테이블을 옛 완료 이력으로 재사용하지 않는다.
- 등록 원천 압축파일의 기존 무결성 검증은 유지한다. 다운로드한 원천의 재전개와 원천 적재 자식 생성은 생략한다.
- 서버가 검증한 전체 manifest를 새 배치 입력에 저장하고 실행 직전에 다시 대조한다. 원천 배치 ID와 재개 대상 ID, 재사용 자식 ID를 남겨 반복 재개의 원천 이력도 보존한다.
- API·CLI 원천 적재는 `SOURCE_STATE` 공유 advisory lock을 사용한다. 재개 실행은 같은 키의 배타 잠금을 정합성부터 MV·게시 종료까지 유지한다. 원천 쓰기끼리의 기존 병렬성·원천별 잠금은 유지한다.
- 재개와 강제 승격·대상 DB 변경을 함께 사용할 수 없다. 새 정합성 보고서의 판정 ID로 MV를 생성하고 새 배치에 연결된 정상 승격 게이트를 적용한다.
- 재개 요청은 Dagster op의 최상위 설정에도 같은 배치 ID를 전달한다. 이전 코드 서버는 모르는 설정을 실행 전에 거부하고, 새 코드 서버는 payload와의 일치를 검사한다. 배포 버전이 섞였을 때 재개 필드를 조용히 무시해 전체 재적재하는 것을 방지한다.

## 결과와 한계

원천이 그대로라면 원천 적재 시간을 반복하지 않고 오류 수정 후 재검증할 수 있다. 새 배치는 원천 자식이 0개이고 정합성·MV 자식만 새로 생성되며, 재사용한 원천은 이전 자식 ID로 추적한다. 재개 실행 시간과 이전 원천 적재·실패·복구의 전체 경과 시간은 구분해 기록한다.

이미 다음 전체분이 테이블을 비우고 다시 적재 중이라면 이전 배치에서 즉시 재개할 수 없다. 먼저 현재 원천 전체가 완료돼야 한다. 실행 중인 코드 서버를 기능 배포 목적으로 교체하지 않는다.

임의 SQL로 이력 밖에서 원천을 변경하는 작업은 지원하지 않는다. 원천 변경은 manifest와 표준 API·CLI 실행 이력 및 잠금에 참여해야 한다.
