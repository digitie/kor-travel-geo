# 전체 배치를 정합성부터 재개

원천 적재가 모두 끝난 뒤 정합성이나 후속 게시에서 실패했다면, 완료 원천을 검증해 재사용할 수 있다. 이전 실패 기록은 보존하고 새 실행에서 정합성·MV·정상 승격을 진행한다. 설계 근거는 [ADR-074](../adr/074-consistency-stage-resume.md)다.

## 관리자 UI

1. **Dagster → 실행 상세**에서 실패·취소된 전체 배치의 `load job` ID를 복사한다. `batch_`로 시작하는 값이며 Dagster 실행 UUID와 다르다.
2. **원천 파일 → 매칭 세트**에서 같은 매칭 세트를 선택한다.
3. **DB 재구성 → 실행 방식 → 완료 원천을 재사용해 정합성부터 재개**를 선택한다.
4. 이전 전체 배치 ID와 복구 사유를 입력하고 **정합성부터 재개**를 누른다.
5. 준비 작업의 원천 검증, 후속 새 배치의 정합성→MV→새 서빙 릴리스까지 확인한다. 정합성이 ERROR이면 다시 차단된다.
6. 새 버전의 실제 Geocode·Reverse를 검증하고 원본 성공 화면과 각 구간의 DB 시작·종료 시각을 기록한다.

## 재개가 거부되는 경우

- 원천 자식 중 실행·대기·실패·취소 작업이 남아 있다.
- 다른 전체 배치나 원천 쓰기가 실행·대기 중이거나, 첫 원천 시작 이후 다른 원천 쓰기가 끼어들었다.
- 매칭 세트·원천 파일·해시·기준월이 달라졌거나 무결성 경보가 있다.
- manifest가 없어 완료를 증명할 수 없거나 건수·기준월·갱신 시각이 완료 작업과 다르다.
- 새 요청이 접수된 뒤 실제 재개 실행 전 원천 manifest가 달라졌다.

특히 SHP 전체분은 대상 테이블을 비운 뒤 다시 채운다. 이 작업을 중지하고 옛 완료 이력만으로 정합성 재개를 시도하면 차단돼야 한다. 재개를 위해 완료 상태나 원천 이력을 직접 변경하지 않는다.

## 이력과 시간

새 배치 입력의 `resume_from_batch_id`는 바로 이전 실패 실행, `source_batch_id`는 원천을 실제로 적재한 배치다. `reused_source_jobs`는 재사용 자식 ID를 기록한다. 과거 자식에 새 실행 ID를 덮어쓰지 않는다.

새 배치의 `started_at`~`finished_at`은 재개한 정합성·MV·게시 시간이다. 이를 원천부터 새로 적재한 전체 소요 시간으로 표시하지 않는다. 원천 적재 실측, 실패·수정 대기와 전체 경과 시간은 별도로 기록한다.
