# Pinvi #650 — 공식 주소 원천으로 전체 도로명 검색 재현

## 최신 사실과 범위

- 최신 Pinvi650 운영 댓글은 약칭/정식 시도명 모두 Geo 직접 호출에서 NOT_FOUND0, 도로명만은67건으로 기록한다. Pinvi/Map 버전만으로 Geo 실행 소스 버전을 추측하지 않는다.
- Geo main d46dfa1(#622)은 구조화한 전체 도로명 검색이다. 기존 독립 PG fixture는 주소40을 합성하고 임의 좌표를 넣었다. 그 통과를 실제 원천/운영 상태의 증거로 해석하지 않는다.
- 로컬 보존202605 공식 Juso 한글 원천 rnaddrkor_gyeongbuk.txt에서 하회종가길67행과40/40-1/68을 별도 주소로 확인했다. 실제 parse_juso_row와 parse_address의 약칭/정식 query 구조 조건은40의 원천 필드와 일치한다. 보존월은202605이고 현재 운영 원천월을 뜻하지 않는다.
- 원래 경북 안동시 풍천면 하회종가길40을 유지한다. 다른 번호로 바꿔 문제를 닫거나 비슷한 번호를 정답으로 반환하지 않는다.

## 구현·검증 계획

1. 원천 archive/member hash와 최소 실제 주소 행을 보존한다. 이름·좌표를 임의 보완하지 않는다.
2. 실제 loader/정규화/서빙 MV/SQL/공개 v2 HTTP까지 단계별로 대조한다. 원래622 전 소스나 통제 변형을 이용해 회귀가 판별하는지 확인한다.
3. 약칭/정식명·40/40-1 분리·없는 번호·지역 제약·좌표 없는 주소·우편번호/구조 필드를 검증한다.
4. 최신 코드에서 재현되면 최소 수정한다. 재현되지 않으면 실제 코드·데이터·서빙 MV 상태를 구별할 읽기 전용 진단 절차와 증거를 제공한다. 합성/보존 원천의 성공만으로 Pinvi650을 완료 처리하지 않는다.
5. WSL ext4 미러에서 게이트와 실제 사용자 검색 UI를 검증한다. 사용자 최신 지시에 따라 운영 접근/배포/테스트는 하지 않는다. 실제 prod 최종 확인은 Claude Code 담당이다.
6. 초안 PR부터 만들고 단계별 원격 commit을 유지한다. 두 독립 전문 적대리뷰와 정확 최종 HEAD의 적용 CI 뒤 일반 merge한다.
